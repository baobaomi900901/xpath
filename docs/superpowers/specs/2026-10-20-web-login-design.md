# WEB 登录靶场

- 在现有 WEB 首页增加“登录测试”，路由 `/login-test`，兼容本地 BrowserRouter 与 GitHub Pages HashRouter。
- 沿用 PageLayout、Ant Design 与现有背景，显示账号登录、手机验证码登录两个页签；初始选择账号登录。
- 账号必须严格等于 `admin`，密码必须严格等于 `1`；手机号必须严格等于 `13922832244`，验证码必须严格等于 `1990`。不自动去除空白，也不进行数值转换。
- 手机登录在验证码输入框右侧提供“发送验证码”按钮，验证码输入框和登录按钮初始禁用；点击发送并校验手机号正确后解除禁用。手机号错误（包括空值）时弹窗提示“手机号错误”并保持禁用。
- 修改手机号时清空验证码并重新禁用验证码输入框和登录按钮，即使改回原手机号也须重新发送。切换登录方式或退出登录后恢复初始禁用状态。发送步骤不可通过 Enter 或提交表单绕过。
- 账号登录的登录按钮初始禁用；仅当账号和密码均非空时启用，清空任意一项即恢复禁用。Enter 或提交表单不能绕过此条件。
- 点击登录或按 Enter 提交（账号登录须填齐两项，手机登录须先发送验证码）。先校验账号/手机号，再校验密码/验证码。分别用模态弹窗显示“账号错误”“密码错误”“手机号错误”“验证码错误”，标题为“登录失败”，可用“确定”、关闭按钮或 Escape 关闭。
- 登录成功进入“网银转账”模拟表单，显示当前登录方式和身份，提供“退出登录”以便重复测试；不持久化登录状态。转账表单的随机化与确认流程见 `2026-10-22-bank-transfer-design.md`。
- 切换页签清空原表单；失败后保留输入以便修正；退出后清空表单。登录控件使用固定 DOM id 和可访问标签供自动化定位；登录后的转账控件使用随机属性。
- 验证码由使用者直接输入，不接入短信服务。仅实现本地模拟靶场。
- 用真实浏览器覆盖首页入口、切换、空值、错误字段、严格匹配、成功、键盘提交和退出；执行 TypeScript 与 Vite 构建。
