# 共享密钥金额签名与 iframe 登记校验

- 用户要求简化为两端相同内置密钥，不使用额外服务或固定 10 条编号。
- `fixtures/bank-transfer-auth.json` v2 保存算法、共享密钥及协议前缀，WEB 与后续 CS 端使用相同配置。
- 金额先校验为正数且最多两位小数，再规范为两位小数文本；随机因子为 12 字节加密随机数，以无填充 Base64URL 编码为 16 字符。
- 使用 Web Crypto HMAC-SHA256 签名 UTF-8 的 `prefix + LF + 金额 + LF + nonce`，取前 12 字节并编码为 16 字符 Base64URL；流水号格式为 `TR_<16字符nonce>_<16字符签名>`，共 36 字符。签名及规范化实现在无依赖的共用模块中。协议前缀为 `bank-transfer:v2`，不再接受旧长编号。
- 点击转账后异步生成，二次确认与成功回执复用不可变快照中的同一编号。取消后重开生成新编号；输入和校验不改变随机 DOM 布局。
- 登记仍用真实 iframe 及 8 项输入；用相同密钥和填写金额验签，拒绝修改的 nonce/签名/金额、不同密钥、旧编号、大小写或空白变化。其余转账字段只执行表单校验，不参与签名。
- 异步期间禁用输入与重复提交，能力/配置错误时提示失败。实现不依赖本机服务、存储或写入网络请求，支持 localhost 及 HTTPS 静态 Pages。
- 共享前端密钥可查看，仅用于靶场模拟。96 位随机因子使重复概率极低，签名截取为 96 位，不能承诺无状态的严格全局历史去重或真实安全鉴权。
- 验证独立 Node HMAC 对照、256 次同额编号不重复、篡改拒绝、iframe 边界、网银到登记联动及构建。
