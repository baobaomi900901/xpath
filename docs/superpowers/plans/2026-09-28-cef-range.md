# CEF Multi-version Range Implementation Plan

> **For agentic workers:** Use subagent-driven-development for the independent launcher task and requesting-code-review before delivery. Keep changes in the user workspace and leave unrelated WEBVIEW2 work intact.

**Goal:** Build and verify CEF 109 / 125 / 128 / 133 / 154 ranges with a version-selecting Python command.

**Architecture:** One native Win32 host compiled against five pinned official CEF SDKs. Each executable embeds the existing WEB routes beside a native menu. Python handles SDK preparation and per-version builds; native/CDP integration verification exercises the actual programs.

**Tech Stack:** C++17, Win32, CEF, CMake, Python standard library, Node built-in WebSocket for verification.

## Global Constraints

- Windows x64; versions exactly 109 / 125 / 128 / 133 / 154.
- Menu labels exactly 点击测试 / 表单测试 / iframe表单.
- Default URLs match the three user-provided GitHub Pages routes.
- Support local WEB via an explicit base URL, without editing WEB source.
- Separate version builds and per-process cache directories; enable platform accessibility.
- Do not modify unrelated WEBVIEW2 files or its documentation.
- No automatic git commits or remote publication.
