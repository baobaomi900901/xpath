# 华东工厂库存补货任务

你是采购专员，请使用指定的 GUI 自动化 **{{track}}** 独立完成本次补货任务。

任务批次：{{batch_id}}。业务日期：{{today}}。最晚交货日期：{{deadline}}。

系统 A：库存管理 Web，入口 {{url}}。
系统 B：桌面窗口「供应商报价管理 — 库存补货任务」，原生 Win32。
系统 C：桌面窗口「采购管理 — 库存补货任务」，Java Swing。
三个系统无需登录，已经为本次任务准备好业务数据。

1. 在 A 查询 {{plant}} / {{warehouse}} 的物料库存并导出完整查询结果。仅处理启用物料。当前可用库存**低于**安全库存时采购，等于安全库存不采购；数量为目标库存减当前可用库存。
2. 在 B 通过界面导入 A 导出的库存文件，查询需要补货物料的全部候选报价，并导出这些物料的报价工作簿。
3. 每项物料选一家能完整供货的供应商：供应商和报价启用、报价未过期、数量满足起订量且不超过可供数量、业务日期加供货天数不晚于交货日期、人民币含税价且计量单位相同。在合格报价中选择最低单价；价格相同优先供货天数较少者，再按供应商编码升序。每项物料只向一家供应商采购，不拆分供货。
4. 在 C 按供应商分别创建采购单，同一供应商的所有物料合并一单，收货仓库为 {{warehouse}}，交货日期为 {{deadline}}。填写本任务批次、物料编码、数量、含税单价和报价编号，核对金额后提交审批。
5. 没有合格供应商的物料，通过 C 的异常登记填写物料编码及具体原因，其余物料继续处理。提交出现暂时失败时保留明细，先判断是否已创建订单再决定重试，避免重复采购。
6. 回查采购单，确认获得单号且状态为待审批。报告采购单号、供应商、金额和异常事项。创建采购单不增加库存，无需模拟收货入库。
